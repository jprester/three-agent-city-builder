# AGENTS.md

Contract for any agent working in this repo. Read fully at the start of every
session, then read `docs/PLAN.md` if it exists: it defines the current work.

When something is ambiguous or a rule seems to block you, do not stop and do not
work around the rule. Pick the most conservative sensible option, log it in
`docs/DECISIONS.md`, put anything only a human can answer in `docs/QUESTIONS.md`,
and continue. The only planned stops are checkpoints defined in `docs/PLAN.md`.

## What this repo is
A three.js web experience whose 3D assets are generated by code. Blender runs
headless as a build tool. Scripts and params are the source of truth; every
binary in `public/` is regenerated from them.

## Binding documents
- `docs/PLAN.md`: the project brief and phases, if present. Human-authored.
- `art/style/style-bible.md`: look and feel. Owned by the human. Change it only when
  `docs/PLAN.md` or the human says so; otherwise propose edits, never deviate silently.
- `art/specs/asset-spec.md`: units, orientation, naming, geometry rules.
- `pipeline.config.json`: pinned Blender version, preview settings, budgets.

## Commands
- `npm run assets` rebuilds changed assets, then layouts, manifest, budget report.
- `npm run assets -- --only 'buildings/*'` limits to matching asset ids.
- `npm run assets -- --force` ignores the cache.
- `npm run layouts` regenerates layouts and manifest only (no Blender).
- `npm run dev` starts the app. URL params: `?layout=<id>`, `?viewpoint=<name>`,
  `?seed=<int>` (regenerates the layout in the browser with that seed).
- `npm run shots` renders every viewpoint and diffs against baselines.
- `npm run shots:approve` accepts current renders as baselines. HUMAN ONLY unless explicitly told.
- `npm run check` typechecks and enforces budgets. Must pass before every commit.

## Never hand-edit (generated)
`public/assets/**`, `public/layouts/**`, `src/assets/manifest.gen.ts`, `build/**`.
Change the generator, def, or layout def, then rebuild.

## Where things go
- New asset: add a def in `art/defs/<category>/<name>.json`. Reuse an existing
  generator with new params before writing a new generator.
- New generator: `art/generators/<category>/<name>.py` exposing `generate(ctx)`.
  Shared logic goes in `art/generators/lib/` or a kit module with a `build_*` function.
- New layout: def in `art/layouts/defs/`, generator in `art/layouts/<name>.mjs`.
  Layout generators run in Node and the browser: no Node APIs.
- Bought or downloaded assets: `art/external/` plus an entry in
  `art/external/manifest.json` (source URL, license, attribution) BEFORE use.
- Colors: add to `art/style/palette.json` and reference by name. No hex literals in generators.

## Generator rules
- All randomness from `ctx.rng` (Python) or `mulberry32(seed)` (layouts). Output must be
  identical for identical inputs; the cache relies on it.
- All tunables are params with defaults read via `ctx.p(...)`, not constants buried in code.
- Absolute imports only (`from lib.mesh import MeshBuilder`) so cache invalidation can trace deps.
- Do not change `tools/blender/export_glb.py` or `tools/optimize.mjs` settings for one asset.

## Verification loop (required for any visual change)
1. Rebuild only what you touched: `npm run assets -- --only '<ids>'`.
2. Look at every image in `build/previews/<id>/`. Judge against the style bible.
3. Iterate until it matches the intent. Say what you checked.
4. For changes visible in the scene, run `npm run shots` and look at `build/shots/`.
   A baseline diff is expected when the change is intended; report it, do not approve it.
5. `npm run check` passes.

## Docs
- `docs/DECISIONS.md`: every non-obvious choice, one line with a reason.
- `docs/NOTES.md`: visual critiques per phase or feature. Be specific and harsh.
- `docs/QUESTIONS.md`: questions only the human can answer.
- `docs/progress/`: copies of screenshots at milestones.

## Pipeline gotchas
- glTF flips V: a Blender UV `v` arrives in three.js as `1 - v`. Shaders reading
  meter-scale facade UVs must undo this.
- Vertex data for custom shaders: the active color attribute exports as COLOR_0,
  custom attributes named `_name` export as `_NAME`. The optimizer keeps them.
- Texcoords outside [0,1] are not quantized (the optimizer logs a skip warning; expected).

## Commits
Generator/def changes and the regenerated outputs go in the same commit.
Keep commits scoped to one asset family or one feature.

## Environment
- Blender: version pinned in `pipeline.config.json`. Binary from `BLENDER_BIN`, then
  config `blender.path`, then the macOS default, then `blender` on PATH.
- Node 22+. No Git LFS: generated GLBs and screenshots are small and committed as regular files.
- Blender is transient: generators run headless and export GLB; `.blend` files are never saved or committed.
