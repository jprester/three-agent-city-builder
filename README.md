# three-agent-template

three.js project template where 3D assets are generated by code (Blender, run
headless) and agents do most of the work. See `AGENTS.md` for the working
contract and `art/style/style-bible.md` for the look. The current project
brief and its phases are in `docs/PLAN.md`.

## First run

```bash
git init && git lfs install
npm install
npx playwright install chromium
npm run assets        # first run pins your Blender version in pipeline.config.json
npm run dev           # http://localhost:5173
npm run shots:approve # create initial screenshot baselines once the scene looks right
```

Blender is found via `BLENDER_BIN`, then `blender.path` in `pipeline.config.json`,
then `/Applications/Blender.app/Contents/MacOS/Blender`, then `blender` on PATH.

## How it fits together

```
art/defs/*.json ──► tools/build-assets.mjs ──► Blender headless (tools/blender/run.py)
                         │                         └─ art/generators/**.py → raw GLB + previews
                         ├─► tools/optimize.mjs (gltf-transform, meshopt) → public/assets/
                         ├─► tools/build-layouts.mjs (art/layouts) → public/layouts/
                         ├─► tools/manifest.mjs → src/assets/manifest.gen.ts
                         └─► tools/check-budgets.mjs
src/ ── loads layouts, instances assets with InstancedMesh
tests/visual/ ── Playwright screenshots per viewpoint vs approved baselines
```

Builds are cached per asset by hashing the def, the generator and its local
imports, the Blender tooling, the palette, the optimizer and the Blender version.

## Not included yet
- Lightmap/AO baking (`tools/blender/bake.py` is the natural next step; bake AO into
  tileable kit textures so instancing keeps working).
- Image textures and KTX2 compression (extend `tools/optimize.mjs`).
- LODs, streaming by district, post-processing (bloom).
